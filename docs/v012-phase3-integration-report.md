## Scope and architecture

This is an *isolated browser-memory preview* that reuses the original Wanderer combat, inventory, equipment slots, item comparison, Forge, Merchant, Runes, nine item slots, dark-fantasy art and assets. No rebuild of the original game, no prototype combat swap, no original save read/import/write, no Firebase deployment or rule changes, no `main` modifications.

The original HTML closure remains the owner of `renderCombat`, `renderStash`, `renderForge`, `renderMerchant`, `equipItem`, `unequipItem`, `totalStats`, `weaponAttack` and the legendary/VFX helpers. The Phase 3 code adds a preview-only router and preparation UI. Native equipment/rune/merchant interactions update only the preview's in-memory `state`, and the `save()` guard still returns early in preview mode.

## Completed

- **Camp**: Original full-body character, five character choices, HP and Mana, every original gear slot with genuine item image, placeholder, rarity border and affinity, preview Expedition level selector, Equipment/Runes, Forge and Merchant. Potions have **no buttons in Camp** and the action is forbidden in the underlying preview API.
- **Planes**: Exactly three choice cards with classic dungeon backgrounds, family glyphs, Waves/loot-roll opportunities, Elite/Boss risk, and a visible marker for event/chest/altar. Event indicators are explicitly marked *preview*, not a promise of extra prizes. Two global rerolls per Expedition (no replenishment between Planes) keep the current Plane risk/event category; the action is unavailable during combat or passive selection.
- **Safe between-Plane preparation**: Current HP/Mana, temporary passives (description/rank), inventory and Runes, gear swaps with original comparison UI, and two test-only Health and two Mana potion charges per Expedition. Health Potion heals up to 35% max HP; Mana Potion up to 40% max Mana; neither is consumed when full. They may be used **only after a completed Plane** while choosing the next route—not before Plane 1, in Camp, in passive draft or during combat.
- **Exploit prevention**: Equipping items or changing Runes recomputes current max stats; lower max HP/Mana immediately clamps the ongoing Expedition resource pool. Re-equipping stronger gear does *not* restore clipped health/mana. Temporary Health/Mana persist and cannot be generated by switching slots.
- **Combat visual parity**: Original character, mob, Elite and boss portraits, backgrounds, debuffs, damage numbers, attack effects, VFX and Legendary rules continue to power automatic one-enemy-per-Wave combat. The preview arena has a fixed responsive height to prevent Elite/Boss portrait growth from resizing combat; all styles are scoped behind `.phase3IntegratedPreview`.
- **Mobile usability**: Responsive nine-slot gear display, 390px layout, readable compact Plane cards, clear potion and reroll controls, and **always-visible Back to Camp/Planes buttons** inside native Equipment/Forge/Merchant pages (the original header navigation is collapsed on mobile).
- **Permanent account systems**: They remain disconnected in preview. Run rewards/gear are in memory, not durable after refresh. Old D1–D200 completion is not converted to Expedition difficulty.

## Phase 3 mobile arena regression fixed

The full audit at commit `6891d8c9` uncovered a **real** layout regression in original inline CSS: `.scene:has(.eliteCombatant)` forces 190px on mobile (and 355px on desktop), overriding the previous Expedition-specific height. After an Elite encounter, the scene jumped from 360px to 190px. This was corrected via the more specific, preview-only `.phase3IntegratedPreview #scene` rule in `online/v012-phase1.css` at commit `236209ee`. The end-to-end browser test now checks actual live combat arena height across Waves, rather than only a nominal minimum.

The completed `39302624342` audit log explicitly confirms **PASS full integrated Expedition on 390px** and **on 1280px**. Both use the original game attack/loot functions and synthetic test-only high-stat equipment. Existing legacy 320px mobile smoke suites also passed, but the *full fifteen-Plane* run covers 390px and 1280px only.

## Known limitations and Phase 4 boundary

- Potions are finite *preview rations*, not yet purchased/stacked/account-persisted items. Define their actual economy, recovery and acquisition in Phase 4; do not infer price or inventory migration.
- Preview Forge/Merchant/Rune logic is reused from the mature D1–D200 economy without any reinterpretation of D200 as Expedition200. The future economy bridge requires explicit balancing/price rules and versioned save safety. No extra account fields have been added.
- Event/chest/altar indicators are informational in this phase; a later gameplay design must specify actual event rewards/risks before showing them as guaranteed. Boss reward/rune policy requires approval.
- There is no persistent Expedition checkpoint or account-linked game. Refresh resets the experimental run; all existing real saves stay untouched.
- Additional real-skill 15-Plane live playthroughs should check long sessions, item frequency, potions and mobile readability under diverse active debuff/boss combinations. Audio parity is not verified.
- The Phase 4 effort should focus on event/economy semantics, balance and compatible save migration, with existing Firebase rules preserved unless a separately approved deployment task changes them. **Do not merge to main** under this Phase 3 report.
