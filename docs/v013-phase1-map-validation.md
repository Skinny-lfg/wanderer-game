## Architecture

The map is an additive, versioned `map.version = 1` snapshot attached to the existing Expedition controller version 2. It stores the Expedition seed, rows/nodes/edges, current and selected nodes, completed nodes, available successors, and the persisted linear auto-advance preference. Realm schedule, event catalog, combat, loot, passive generation, and save schema remain owned by the existing controller/runtime.

The 15-row graph has a single start node, three nodes in Realms 2–14, and one final boss node in Realm 15. Edges form overlapping forks: each intermediate node leads to two next-row lanes; every row remains reachable and every lane can reach the boss. Encounter kind is taken from the existing Expedition calendar, so every possible path retains exactly that calendar's two Elites and three or four Events. The selected Realm affinity is carried into the next fork through the existing affinity influence mechanism; offers still obey the three-affinity cap and the existing affinity planner.

Choosing an available map node immediately starts its Realm. Clearing a Realm preserves the mandatory result/passive flow and then returns to the map. A one-node final boss route starts automatically by default. The map has a saved “Linear route auto-advance” toggle so players can pause before the boss and manage equipment. Full Bag or overflow disables route entry; Bag, equipment comparison/equip, stats/passives, potions, vitals, and extraction remain available from the map workspace.

Existing version-2 checkpoints without a map remain valid and use their prior route flow. New maps are validated and restored without regenerating the graph or resetting rerolls. Completed node history is checked against the Realm reward history before restore. This is additive and non-destructive; no save schema migration or real-save access was required.

## Experience comparison

The comparison counts navigation actions only; mandatory affinity, passive, Event, Rune, and route decisions are retained.

| Measure | v0.12 route flow | v0.13 map flow | Result |
|---|---:|---:|---|
| Navigation clicks after a mandatory reward on a branching route | Exit Realm + select Realm + Enter Realm = 3 | Select one connected map node = 1 | 2 fewer per branch transition |
| Realm 14 to final boss | Exit + select + Enter = 3 | 0 with auto-advance; 1 after pausing | 3 fewer by default |
| Initial Realm after affinity | Select Realm + Enter = 2 | Automatic root entry = 0 | 2 fewer |
| Branching route decisions before Realm 15 | 13 | 13 | Preserved |
| Mandatory passive/Event decisions | Existing rules | Existing rules | Preserved |
| Combat duration / Expedition wall-clock time | Baseline simulation | Not meaningfully timed by forced-win browser fixtures | No player-time claim made |

The 174-row `simulate:v012` output exactly matches the Phase 0.2 baseline row-for-row (174/174), including timeout count and outcomes. That checks combat/economy determinism under the same legacy route fixture. This is stronger evidence for unchanged simulation results than synthetic wall-clock timings. A human playtest is still needed to measure real menu dwell and the combat share of total session time.

## Regressions found and resolved

- Legacy combat/economy fixtures initially instantiated the production map and altered their controller RNG snapshots. The test harness now opts into legacy navigation for tests whose purpose is unchanged v0.12 engine parity; dedicated browser and controller tests exercise the production map.
- Legacy browser tests expected a second Enter Realm click after selecting an offer. They now assert node selection starts the Realm directly.
- The full-Bag UI originally blocked entry only in runtime validation. Available map nodes now disable visibly and display a Bag-full message; extraction remains enabled.
- A source-contract test expected the former manual event-exit expression. It now asserts that the passive is resolved before the automatic map return.
- Browser suites regenerate checked-in screenshots in unrelated UI audit folders. Those generated changes were restored; only the two Phase 1 map screenshots are retained here.
