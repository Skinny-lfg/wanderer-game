## Stage 3 implemented

The CLI now hashes the evaluated VM units in order, including replacement bytes and the injected inline entry, plus the simulator's local CommonJS dependency graph, harness and Node version. A separate replay digest includes scenario options and harness controls. Each fight reports a digest of its detached initial native state, policy, update calls, native elapsed seconds and observed reserve entries. The synthetic account, locked gear and clock substitutions are identified in the report. A naturally generated room in this runner is still entered with a synthetic account.

The parity test uses a real Chromium JS environment with the page's original classic script tags in browser order and a second Node VM driven by the actual CLI fight loop. Both have the same seeded setup, frozen wall clock, synthetic gear/rune, isolated storage and manually stepped updates. The browser replays explicit recorded target slots through the shared validated action. State is compared before combat and after every update, including final rewards, active/reserve enemies, target and group clocks, casting deadlines, stats, build, HP/MP and room. The regression requires actual damage, a timed cast, a target change and reserve replacement. Neither auth startup, real player progression, click hit-testing nor wall-clock scheduling is covered. This trace does not establish all-affinity or all-Boss parity.
