Branch: `audit/v013`. Source entrypoint: `index.html`. The C8 inventory was generated by examining the *current* entrypoint and the real account/feedback/leaderboard modules, not by assuming that every historical function is live.

|---|---:|

## Tests, accessibility and limitations

- C8 adds `tests/v013-c8-ui-wiring.test.cjs` to the required gameplay gate. It checks that each currently declared data attribute is accounted for, 29 key action families are rendered and queried, and the three external online header actions have matching module bindings.
- Native gameplay and previous Chromium journeys cover Camp, talents, Forge, Merchant, Apothecary, Runes, inventory, Realm selection, map, events, Shrine, Boss and extraction. The feedback module has its own browser regression with click/Escape closure.
- **No confirmed live UI control with zero usable handler** was found in this static+journey scope. This is **not** a proof that every seed/state/browser/keyboard combination is reachable. In particular it does not prove exhaustive execution of all 76 event registrations.
- Data-only markers like `data-target` are selectors used for VFX rather than independent gameplay features; a selector is not automatically a button.
- The C6/clean-sheet static scanners found zero missing active imports and zero retired controller references in their observed scope. They do not establish universal dead-code elimination, so no module was removed from the playable runtime on a speculative basis.

**Closure verified:** Current-only UI guards ran within `npm run test:v013` (295/295 total) on `e9e590ba5ce62bca96e21e1001ca6088613106a7`; final C7 passed 4/4. Live service and full dynamic state coverage remain unvalidated.
